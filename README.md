Source for hivecommons.dev (GitHub Pages). Static site: `index.html`, `style.css`, and
`assets/` — no build step.

Custom domain is pinned via `CNAME`. `llms.txt` carries a short machine-readable summary
for LLM crawlers (its integration and sponsor lists are gated against `index.html` by
`scripts/llms-txt.test.mjs`), and `sitemap.xml` lists the canonical top-level pages (not every
shortcut redirect) for `robots.txt`'s `Sitemap:` entry — when adding a new top-level
page, add it to `sitemap.xml` too.

`.well-known/security.txt` is the RFC 9116 security contact for the domain (it points at
`security@hivecommons.dev` and the org `SECURITY.md`). Its `Expires:` field must be at
most a year out, so bump it once a year. GitHub Pages builds the site with Jekyll, which
drops dot-directories unless they are listed in `_config.yml`'s `include:` — that is the
only reason `_config.yml` exists; keep `.well-known` in it.

## Shortcut redirects

Short paths like `/docs`, `/code`, `/discord` are meta-refresh redirect pages. All of them
are generated by `make-redirects.sh`: edit the `MAP` at the top of the script, run
`./make-redirects.sh`, then commit the regenerated `index.html` files — don't hand-edit
them, since a future run of the script will silently overwrite any hand edit.

`scripts/check-redirects.sh` enforces this: it regenerates the pages into a scratch
directory and fails if any committed redirect page is missing from `MAP`, any `MAP`
entry has no committed page, or a committed page differs from what the script emits.

## Checks

The **Link check** workflow (`.github/workflows/links.yml`) runs its `links`, `test` and
`redirects` jobs on every pull request and on every push to `main`, so commits pushed
straight to `main` are checked too and `main` carries a same-named baseline to compare a
red PR job against.

- `scripts/check-links.sh [--external-warn]` — resolves every internal link/anchor and
  probes external URLs (CI runs it with `--external-warn` on PRs and pushes; the weekly
  scheduled run and manual dispatch hard-fail on broken external links). Besides every
  committed page and the `make-redirects.sh` map, it checks the URI fields of
  `.well-known/security.txt` (RFC 9116 `Contact`, `Canonical`, `Policy`,
  `Acknowledgments`, `Hiring`) and every `https?://` URL in `llms.txt`, so a rotted
  security-contact link or machine-readable-summary link is reported too. It
  also checks `og:image`/`og:url`/`twitter:image` `content=` URLs and JSON-LD
  `url`/`logo`/`codeRepository`/`sameAs`/`license` values.
- `scripts/check-links.test.sh` — fixture-based self-test of the link checker; runs
  offline (fake `curl`).

  `push` trigger covering `main`; "every pull request" needs `pull_request`; "weekly"
  needs a `schedule` with a plain weekly cron; a literal cron `` `M H * * D` `` must equal
  the workflow's `cron:`; "manual dispatch" needs `workflow_dispatch`; back-ticked pull
  request activity types (`closed`, …) must be exactly `pull_request.types`; and "code
  scanning" needs a `github/codeql-action/upload-sarif` step. Every committed workflow
  must be introduced that way in this README, so new automation cannot land undocumented.
  Each rule has a fixture self-test. Zero dependencies.
- `node --test scripts/workflow-hardening.test.mjs` — static gate over the supply-chain
  hardening of every workflow under `.github/workflows/`: every `uses:` is pinned to a
  40-hex commit SHA with a trailing `# <version>` comment (`./` local actions exempt,
  `docker://` images by `@sha256:` digest), including the reusable-workflow `uses:`; the
  workflow declares a top-level `permissions:` block and nothing grants `write-all`; every
  `actions/checkout` step sets `persist-credentials: false`; and every job with `runs-on`
  sets `timeout-minutes`. OpenSSF Scorecard reads the same files but runs only on `main`
  and a lower score fails nothing, so a tag re-pin or a dropped `persist-credentials: false`
  would otherwise merge green. Each rule has a fixture self-test. Zero dependencies.
- `node --test scripts/dependabot-config.test.mjs` — static gate over
  `.github/dependabot.yml`, the only thing that moves the SHA pins
  `workflow-hardening.test.mjs` requires: the file exists and is `version: 2`; every
  `updates:` entry names a `package-ecosystem` Dependabot knows, a `directory:` and a
  `schedule.interval` it accepts; every ecosystem the tree contains (workflows under
  `.github/workflows/` → `github-actions`, a root `package.json` → `npm`, …) is covered by an
  entry at `/`, no entry names an ecosystem the tree lacks, and no two entries cover the
  same ecosystem and directory. Without it a deleted or mistyped config leaves every pin
  valid but silently rotting — Scorecard's Dependency-Update-Tool check reads the same file
  but only on `main`, and a lower score fails nothing. Each rule has a fixture self-test.
  Zero dependencies.
- `node --test scripts/owners-file.test.mjs` — static gate over every `OWNERS` file in the
  tree and `OWNERS_ALIASES` when present, the files prow's `approve` plugin and tide read to
  decide who may `/approve` and whether a PR merges: the root `OWNERS` exists; every file is
  flat YAML of `key:` blocks of `- item` lines indented with spaces; only keys prow knows
  (`approvers`, `reviewers`, `emeritus_approvers`, `emeritus_reviewers`, `labels`, `options`
  with its boolean flags); the root file names at least one approver; every entry is a
  syntactically valid GitHub login (no `@`, no email) or an alias declared in
  `OWNERS_ALIASES`; and no list repeats an entry or names someone as both active and
  emeritus for the same role. Prow treats every one of those mistakes as "no approvers
  here", so without the gate a typo would land green and surface only as PRs that never
  merge. Login syntax only — the gate has no network access. Each rule has a fixture
  self-test. Zero dependencies.
- `node --test scripts/doc-paths.test.mjs` — static gate over the repository paths named
  in backticks by `README.md` and `runbooks/*.md`: a word in an inline code span is a
  path claim when it starts with `./`, or when its first segment is a committed top-level
  directory or it is root-absolute and it ends in a file extension or `/` (so
  `/404.html`, `/stories/` and `scripts/*.sh` are checked, while URL-path examples such as
  `/some/deep/path`, action references and bare basenames are not); every claim must
  resolve to a committed file or directory, a `*` in the last segment matching at least
  one. `page-meta.test.mjs` resolves Markdown links only and `ci-wiring.test.mjs` checks
  that every existing gate is described here, not that every described path still exists,
  so a renamed script or dropped workflow would otherwise leave the prose pointing at the
  old name. Each rule has a fixture self-test. Zero dependencies.
- `node --test scripts/issue-forms.test.mjs` — static gate over `.github/ISSUE_TEMPLATE/`:
  `config.yml` and every form parse and `blank_issues_enabled` is boolean; every
  `contact_links[].url` is `https` and a `hivecommons.dev` URL resolves to a committed
  page; `body[].id` is unique within a form and every `type` is one of GitHub's five
  form element types; every `labels[]` entry is in `KNOWN_LABELS`. GitHub silently falls
  back to a blank issue when a form fails to parse, so CI would otherwise stay green on a
  broken form. Each rule has a fixture self-test. Zero dependencies.
- `node --test scripts/artifact-registry.test.mjs` — advisory (report-only) registry
  check: every tracked file should be covered by a page/asset/script class gate or named
  literally in a `scripts/*.test.mjs` or `scripts/check-*.sh`; unregistered files are
  printed as a warning and do not fail the run yet. Add a file to `UNGATED_OK` to exempt
  it (a reviewed diff, not silence). Zero dependencies.

## Local preview and running the checks

Prerequisites: Python 3 (any recent version) for previewing, and Node.js (the `node --test`
runner) for the gates; no `npm install` is needed.

```sh
python3 -m http.server 8000     # then open http://localhost:8000/
node --test scripts/*.test.mjs  # every Node gate (what CI runs)
scripts/check-links.test.sh     # link-checker self-test (offline)
scripts/check-redirects.test.sh # redirect-gate self-test (offline)
scripts/check-redirects.sh      # redirect-page drift gate
node scripts/update-csp-hashes.mjs  # after editing an inline <script>: refresh its CSP hash
```

Run these from the repository root before opening a PR. The previewed pages are served
from the checkout as-is, so root-absolute links (`/stories/`) resolve locally the same way
they do on the live site. Each gate is described under [Checks](#checks).

## Availability monitoring

The **Link check** workflow runs every Monday at 09:17 UTC, every 6 hours for
the availability probe alone, and can also be run manually from the Actions tab.
On those runs, its separate `availability` job
requests the live homepage, `/stories/`, a sample of the shortcut redirects and
`/404.html` over HTTPS and fails unless every one returns HTTP 200 (the list is
kept in step with the committed pages by `scripts/availability-probes.test.mjs`).
Connection/TLS errors and timeouts also fail the job. Requests
have bounded retries for transient failures. PR and push-to-`main` runs only check
the checkout; they do not probe the production site.

Review failed runs in Actions and configure GitHub Actions notifications for the
workflow if you operate the site. See [the availability runbook](runbooks/availability-failure.md)
for a failing probe and [the rollback runbook](runbooks/release-rollback.md)
for a bad deploy. This 6-hourly probe is a basic availability signal,
not continuous uptime monitoring or a check after every deployment. The 6-hourly
runs skip the heavier jobs; the full link check runs weekly. External link
failures remain warnings in the separate `links` job.

Traffic analytics and shortcut usage tracking are not configured. Adding them
requires an operator to choose a backend/property and settle privacy and consent
requirements first (see [issue #73](https://github.com/hivecommons/hivecommons.github.io/issues/73)).

## Repository automation

**OpenSSF Scorecard** (`.github/workflows/scorecard.yml`) — Runs OpenSSF security scorecard analysis on every push to `main`, weekly (cron `23 5 * * 1`), and on manual dispatch from the Actions tab. Results are published to GitHub's code scanning dashboard.

**Close linked issues** (`.github/workflows/close-linked-issues.yml`) — Automatically closes issues linked to a closed pull request when a PR transitions to `closed`.

**Incident response** — When a bad deploy or incident impacts visitors of `hivecommons.dev` (broken pages, dead redirects, domain issues), use the [postmortem template](runbooks/postmortem-template.md) to document it blamelessly and fact-based. Coordinate recovery using the [release-rollback runbook](runbooks/release-rollback.md).
